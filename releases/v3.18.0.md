# Nexus Prime v3.18.0

`v3.18.0` hardens the full client lifecycle so bootstrap and orchestrate remain the required start, but no longer imply that token planning, governance checks, durable memory storage, or session DNA are optional. The runtime behavior, bootstrap artifacts, protocol docs, and release surfaces now tell one consistent story.

## Highlights

- `nexus_session_bootstrap` now returns a mandatory protocol checklist.
- `nexus_orchestrate` now returns a mandatory remaining-steps footer.
- MCP responses now prepend lifecycle warnings for missing `nexus_store_memory` and missing `nexus_optimize_tokens` when Nexus-visible intent suggests they are required.
- Shared instruction generation now teaches the same lifecycle to Codex, Claude Code, Opencode, Cursor, Windsurf, and Antigravity/OpenClaw.
- Public docs, feature registry output, and release surfaces now match the runtime lifecycle contract.

## Shipped Changes

- Added lifecycle phase tracking to MCP session telemetry (`pre-bootstrap`, `bootstrapped`, `orchestrated`, `working`, `closing`).
- Added best-effort file-intent tracking from tool arguments only, without claiming visibility into arbitrary shell or editor reads.
- Replaced XML planning nudges with plain-text `MANDATORY NEXT STEPS`.
- Tightened tool descriptions for `nexus_optimize_tokens`, `nexus_mindkit_check`, `nexus_store_memory`, `nexus_session_dna`, and `nexus_ghost_pass`.
- Rewrote repo and client bootstrap instructions so `nexus_orchestrate` does not replace during-work or session-close steps.
- Updated protocol, integrations, knowledge-base, README, and feature-registry surfaces to remove “manual/diagnostic only” drift for lifecycle tools.
