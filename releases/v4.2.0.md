# Nexus Prime v4.2.0

`v4.2.0` is the reliability release for the operator path investors will actually see: orchestration that no longer blocks on irrelevant review gates, memory that stays scoped to the right repo and project, and a dashboard that exposes optimization, trust, and selection reasoning instead of burying it in internal runtime state.

## Highlights

- Review gates are now task-aware and evaluated per gate, so technical runs stop failing behind unrelated PM or marketing blockers.
- Memory now carries repo, workspace, and project provenance; noisy runtime chatter is routed away from the primary durable working set.
- The dashboard surfaces token optimization, gate reasoning, selection audit, memory container counts, interpretation issues, and pre-compaction backup state as first-class operator truth.
- Public release surfaces now tell the same story across the changelog, README, docs landing page, and GitHub release notes.

## Shipped Changes

- Added the internal `NexusLayerAdapter` seam for knowledge, reflection, and workspace summaries without changing public MCP names.
- Reworked specialist and workflow selection so low-confidence cross-domain picks are rejected more aggressively and bounded worker parallelism remains explicit.
- Updated memory control-plane flows to preserve repo/project-aware scope, separate workspace/profile/shared/inbox lanes, and retain backup metadata before compaction-style writes.
- Expanded dashboard summary and surface payloads with token optimization, gate status, memory containers, selection-audit reasoning, interpretation issues, and trust backup signals.
- Updated public docs to explain the new release in the README release history and docs-site changelog block.
