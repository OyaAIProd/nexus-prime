🗂 Runtime Contract

Nexus Prime stays intentionally simple at the public contract layer:

1. nexus_session_bootstrap(goal, files?)
2. nexus_orchestrate(prompt)
3. Persist packet, ledger, token telemetry, provenance, and session DNA
4. Inspect runtime truth in the dashboard or via MCP

Low-level tools remain available for diagnostics and expert override, but they are not the default path for external clients.

🛠️ Building on Nexus Prime

Extend the shipped control plane through the supported operator surfaces instead of patching core entrypoints:

  • Install client-native bootstrap files with nexus-prime setup <client> or setup all.
  • Inspect or override the planner with nexus_plan_execution.
  • Ground runs with session-first RAG collections and inspect what the runtime actually retrieved.
  • Use the feature catalog and runtime catalog to understand what ships before adding new surfaces.

Setup in 5 Minutes.

Install the MCP server, let Nexus auto-establish bootstrap artifacts, and verify the orchestrate path. Included profiles bypass manual JSON wiring.

// Install the control plane globally
npm install -g nexus-prime

// Start the MCP server daemon
npx nexus-prime mcp

// Autogenerate workspace bootstrap files
nexus-prime setup codex
# Bind your local .nexus-prime identity directory
docker run -d \
  --name nexus-prime \
  -v ~/.nexus-prime:/root/.nexus-prime \
  sirad/nexus-prime:latest mcp
// Use our included profiles to bypass manual JSON wiring
nexus-prime setup cursor
nexus-prime setup claude
nexus-prime setup windsurf
nexus-prime setup all
